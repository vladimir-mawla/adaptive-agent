# ADR 0004 — M4 the invariant gate: the signature deviation, the registry construction mechanism, exactly which mutation attacks it stops, and what M4 does not claim

- **Date:** 2026-09-30
- **Status:** accepted
- **Phase / milestone:** M4 (BUILD) — `lib/invariants/`

## Context

`.genesis/PLAN.md` §3 (M4) commits this milestone to `gate(delta: BehaviorDelta, invariants:
Invariant[]): "eligible" | "frozen"` — "evaluated purely on `delta.knob` against the domain's frozen
invariant list, independent of any evidence" — and to refusing "to let any function under
`lib/invariants/**`'s own non-test source construct, mutate, or spread a modified invariants array...
invariants are read, never written, from inside the running system." This ADR records the shape
actually shipped, why it differs from the plan's literal text, the exact enforcement mechanism behind
"no runtime mutation path," and — per this account's own standing discipline against silently
resolving an ambiguous plan (see `0001-contracts.md`, `0003-evidence.md`) — a mismatch this milestone's
own task brief carried against the plan, and how it was resolved.

## Decision 0 — a mismatch between this milestone's own task brief and the plan/DONE.html, resolved in favor of the locked, pre-existing sources

This milestone's own build task named the scope as `lib/gate/**`. Both `.genesis/PLAN.md` §3 M4
("**Files it owns:** `lib/invariants/gate.ts`, `lib/invariants/__tests__/*.test.ts`,
`lib/invariants/__tests__/architecture.test.ts`") and the LOCKED `.genesis/DONE.html` (`<td>M4</td><td>The
invariant gate (<code>gate</code>)</td>...<td><code>npm test -- lib/invariants</code></td>`) — both
written 2026-09-22, before this build session, and both read in full before writing anything, per this
milestone's own instructions — agree with each other and name `lib/invariants/**`, not `lib/gate/**`.
`lib/contracts/invariant.ts`'s own header (M1, frozen, 2026-09-23) independently corroborates the same
path a third time: "M4's `lib/invariants/**` (unbuilt) is where that scan belongs, once there is a
registry and gate function to scan." Three independent, pre-existing, authoritative sources agree with
each other and disagree with this session's own task brief. This milestone builds under
`lib/invariants/**`, treating the task brief's `lib/gate/**` as its own transcription slip rather than
a deliberate rescoping — and flags it here, in the PR, and in the handback report, rather than silently
picking one without saying so. If `lib/gate/**` was in fact intended as a deliberate rename, that is a
rescoping decision for a human to make explicitly, not one this milestone should infer and act on
unilaterally.

## Decision 1 — signature deviates from the plan's literal text: `gate(delta, registry: InvariantRegistry<KnobId>)`, not `gate(delta, invariants: Invariant[])`

Matching the identical "signature deviates from the plan's one-line text, documented, not silently
patched" shape `0003-evidence.md` already set for `tally`, for two independent reasons:

1. **`KnobId` is generic on `Invariant`/`BehaviorDelta`, not a fixed union (M1, frozen).** A bare,
   unparameterized `Invariant[]` parameter would silently widen back to `Invariant<string>` — the exact
   free-text hole `0001-contracts.md` Decision 3 already discloses and does not want re-opened here.
   `gate<KnobId, KnobValue>(delta: BehaviorDelta<KnobId, KnobValue>, registry: InvariantRegistry<KnobId>)`
   threads the SAME `KnobId` through both parameters, so a delta and a registry built for two different
   domains' knob unions fail to compile together (checked directly: a scratch call passing a
   `BehaviorDelta<"a"|"b">` alongside an `InvariantRegistry<"c"|"d">` fails with `TS2345`, confirmed then
   discarded, not committed) rather than silently comparing two unrelated string sets that happen to
   both widen to `string`.
2. **A bare `Invariant[]` parameter cannot BE the "registry" the plan's own prior milestone already
   named.** `lib/contracts/invariant.ts`'s own header (M1, frozen) states directly: "M4's
   `lib/invariants/**` (unbuilt) is where that scan belongs, **once there is a registry and gate
   function to scan**." A plain array has no construction step to gate access through, and TypeScript's
   `readonly` modifier is compile-time only — erased at runtime, exactly this milestone's own task names
   ("`readonly` in the type system is erased at runtime"). An opaque, branded `InvariantRegistry<KnobId>`,
   mintable only through `createInvariantRegistry`, is what makes "declared once per domain at setup and
   not extensible at runtime" (plan §2) a constraint on the actual value `gate` consults, not a comment
   next to a plain array anyone could still push to without a type error.

**Final shape, exactly as shipped** (`lib/invariants/gate.ts`):

```ts
export type InvariantRegistry<KnobId extends string = string> = readonly Invariant<KnobId>[] & {
  readonly [invariantRegistryBrand]: "InvariantRegistry";
};

export function createInvariantRegistry<KnobId extends string = string>(
  invariants: readonly Invariant<KnobId>[],
): InvariantRegistry<KnobId>;

export function gate<KnobId extends string = string, KnobValue = unknown>(
  delta: BehaviorDelta<KnobId, KnobValue>,
  registry: InvariantRegistry<KnobId>,
): "eligible" | "frozen";
```

## Decision 2 — "immune to evidence volume" is a structural claim (no parameter exists to receive evidence), proven both by the type system and by a real, large tally

`gate`'s signature has no third parameter of any kind. This is a stronger guarantee than "gate reads
evidence but disregards it": there is no route by which an `EvidenceTally`, an `Episode[]`, or a policy
constant reaches this function's logic at all — passing one is a `tsc` arity error (`TS2554`) at the
call site, not a silently-ignored extra argument. `__tests__/gate.test.ts`'s own
`@ts-expect-error`-guarded test proves this directly (an unused `@ts-expect-error` is itself `TS2578`,
making the proof real, the same discipline `0001-contracts.md`'s own `@ts-expect-error` proofs use).

This structural claim is also proven empirically, not only by reading the signature:
`__tests__/immunity.test.ts` builds a REAL `EvidenceTally` via `lib/evidence`'s already-built, frozen
`tally()` from 10,000 synthetic `"helped"` episodes spread across 10,000 distinct contexts (not a
replay storm — the maximally corroborated shape the plan itself names as the one that must still not
move a frozen knob), confirms that tally genuinely clears any bar M5 (unbuilt) could plausibly set
(`distinctContexts: 10_000`, `helped: 10_000`, `neutral: 0`, `harmed: 0` — comfortably above plan §3
M5's own disclosed `MIN_DISTINCT_CONTEXTS_ADOPT = 3`), and then calls `gate(delta, registry)` — a call
that structurally cannot receive that tally — and confirms `"frozen"`. A second case in the same file
confirms the reverse is also true: the IDENTICAL 10,000-episode storm against a delta targeting a
**non**-invariant-protected knob resolves `"eligible"`, ruling out the possibility that `gate` is simply
returning a constant regardless of input (see Decision 4's gutting experiment for the direct proof of
that specific alternative failure mode). A third case confirms zero episodes against the
invariant-protected knob also resolves `"frozen"` — the decision depends on neither an abundance nor an
absence of evidence, because it never depends on evidence at all.

`__tests__/immunity.test.ts` imports `lib/evidence/tally.ts`, a sibling module — this is safe for the
modular-architecture gate (`.genesis/DONE.html` §2: "Dependency direction inward, zero cycles:
`lib/contracts` → `lib/evidence` and `lib/invariants` → `lib/arbitrate`...") because that gate is about
NON-TEST SOURCE. `lib/invariants/gate.ts` itself imports nothing from `lib/evidence` — confirmed
directly by `__tests__/architecture.test.ts`'s own import scan (Decision 3 below), not merely asserted
in this document.

## Decision 3 — "no runtime mutation path": the exact enforcement mechanism, and precisely which attacks it stops

`createInvariantRegistry` enforces immutability with **two independent mechanisms, stacked, not one
standing in for the other**:

1. **A defensive copy** — `invariants.map(invariant => ({ ...invariant }))` builds a brand-new array of
   brand-new element objects before anything is frozen. This is what makes the guarantee survive a
   caller who keeps working with their OWN original array/objects after minting a registry from them —
   mutating the caller's original has zero effect on the registry `gate` will ever consult, because
   after construction the two no longer share a single object reference anywhere.
2. **`Object.freeze` on the copied array AND on every copied element, independently.** Freezing only the
   array would stop `push`/`pop`/`splice`/index-assignment on the array itself but leave each
   `Invariant` object inside it mutable (`registry[0].description = "..."` touches only one element, not
   the array) — so both layers are frozen separately.

**What this stops, each checked by a dedicated test in `__tests__/registry.test.ts`, not asserted in
bulk:**

| Attack | Stopped? | Mechanism | Test |
|---|---|---|---|
| Array-mutating methods (`push`/`pop`/`shift`/`unshift`/`splice`/`sort`/`reverse`/`fill`/`copyWithin`) on the returned registry | **Yes — throws `TypeError`** | `Object.freeze` on the array (non-extensible, every index non-configurable) | "ATTACK: array-mutating methods..." |
| Index assignment (`registry[0] = x`) on the returned registry | **Yes — throws `TypeError`** | Same | "ATTACK: index assignment..." |
| `Object.defineProperty(registry, i, {...})`, existing or new index | **Yes — throws `TypeError`** | Same | "ATTACK: Object.defineProperty..." |
| Reassigning a field on a returned ELEMENT (`registry[0].description = "x"`) | **Yes — throws `TypeError`** | Elements frozen independently, not only the array | "ATTACK: reassigning a field on a returned ELEMENT..." |
| Mutating the CALLER's own pre-registry array/objects after construction | **Yes — has zero effect on the registry** (does not itself throw — the caller's own, now-disconnected copy is still theirs to do what they like with) | Defensive copy severs the reference | "NOT AN ATTACK THIS FUNCTION STOPS, BY DESIGN — decoupling, not refusal..." |
| A deliberate `someMutableArray as unknown as InvariantRegistry<K>` cast around a plain, never-frozen array | **No — not stopped, disclosed** | The brand is erased at runtime; `gate` does not call `Object.isFrozen` on its input | "DISCLOSED RESIDUAL, NOT CLOSED BY THIS FUNCTION..." |

**Why `gate` itself does not call `Object.isFrozen(registry)` as a defense-in-depth runtime guard —
considered and left out, not an oversight:** `gate`'s own return type is fixed at exactly
`"eligible" | "frozen"` (plan §3's own literal text); there is no third outcome to report "this registry
was not properly constructed" through without either inventing a value outside that closed set (the
same "silently wrong tally" class of mistake `0003-evidence.md` refuses for a different reason) or
throwing (which this project's own established pattern — `lib/evidence/tally.ts`'s own fail-closed
design — treats as a worse failure mode than a typed result for ordinary hostile input). A caller
willing to write a visible `as unknown as InvariantRegistry<K>` cast has already chosen to bypass this
module's own type system deliberately; adding an `Object.isFrozen` check would only change WHERE that
deliberate bypass surfaces (a thrown error inside `gate`, at some later, unrelated call, instead of at
the cast site itself), not whether it is possible — the identical judgment call
`lib/contracts/adaptation-decision.ts`'s own `assertFrozenCitesNoEvidence` makes for the structurally
identical cast residual on `FrozenDecision` (that function is offered as an OPT-IN check a consumer can
choose to call, not built silently into every read of a `frozen` value). This milestone's own task asked
to "state precisely which attacks each stops and which it does not" rather than to close every attack —
the residual is disclosed, not solved, matching the house standard `0001-contracts.md` and
`0003-evidence.md` both already set for their own analogous casts.

**The source-scan half of "no runtime mutation path," matching the plan's own falsifiable check
("a grep-based architecture test confirming no assignment expression under `lib/invariants/**`
(excluding tests) writes to any array or object whose declared type is `Invariant[]`"):**
`__tests__/architecture.test.ts` scans every non-test `.ts` file under `lib/invariants/` (comments
stripped, same discipline `lib/contracts/__tests__/architecture.test.ts` already established) for any
array-mutating-method call or index-assignment expression. `gate.ts`'s own `.map` call (inside
`createInvariantRegistry`, building a fresh copy) is confirmed NOT to trip this scan — construction of a
new array is not what plan §3 refuses; mutating an EXISTING one in place is. A second scan in the same
file confirms `gate.ts` imports nothing from `lib/evidence`, backing Decision 2's architecture claim
with a real test rather than only a code-reading assertion.

## Decision 4 — falsifiability, run for real, not just described

**Experiment 1 — `gate` itself gutted to `return "eligible";` unconditionally** (minimal, uncompensated:
no call-site change, no compensating check added elsewhere), full suite (`npm test`) re-run:
**230 of 237 tests still passed**, decomposed, not reported alone:

- **215** are M1/M2/M3's own tests (pre-existing, untouched by this milestone), which never call `gate`
  at all and could not have detected this regardless of what `gate` does.
- **12** never call `gate` either, but are this milestone's own: all 7 of `__tests__/registry.test.ts`
  (tests `createInvariantRegistry`, not `gate`) and all 5 of `__tests__/architecture.test.ts` (a source
  scan).
- **3** do call `gate`, but themselves expect `"eligible"` and so pass trivially against a
  constant-`"eligible"` function, by design, not by a blind spot: 2 in `gate.test.ts` ("returns
  'eligible' when delta.knob matches no invariant", "returns 'eligible' against an empty registry") and
  1 in `immunity.test.ts` ("the same 10,000-episode tally against a non-invariant-protected knob...").
  215 + 12 + 3 = 230, matching the passing count above.
- **The remaining 7 all failed, correctly**: every test, in either file, asserting `gate(...) ===
  "frozen"` — 5 of the 7 `gate.test.ts` cases ("returns 'frozen' when delta.knob matches", "matches
  purely on the knob string", "is a pure function...", "checks every invariant in a multi-invariant
  registry", "STRUCTURAL PROOF...") and 2 of the 3 `immunity.test.ts` cases (the 10,000-episode-storm
  case and the zero-episode case, both asserting `"frozen"`). 230 + 7 = 237, the full suite size — the
  arithmetic closes.

The file was restored **byte-for-byte** (`diff` against the pre-sabotage backup returned no output) and
the suite returned to 237/237.

**Experiment 2 — `Object.freeze` removed from `createInvariantRegistry`** (minimal, uncompensated: the
defensive copy itself was left intact, only the two `Object.freeze` calls were deleted), full suite
re-run: **exactly 5 of 237 tests failed** — all five of `__tests__/registry.test.ts`'s own
mutation-attack assertions ("array-mutating methods...", "index assignment...", "Object.defineProperty
...", "reassigning a field on a returned ELEMENT...", and "Object.isFrozen is true..."), each now
reporting that a mutation which should have thrown `TypeError` instead silently succeeded. All 232 other
tests — including `registry.test.ts`'s own remaining 2 tests (the decoupling test and the
disclosed-cast-residual test, both of which depend on the defensive copy, not on `Object.freeze`, and so
were correctly unaffected) and every `gate`/`immunity`/`architecture` test — stayed green, confirming
this sabotage's blast radius was isolated to exactly the mechanism it broke. The file was restored
byte-for-byte and the suite returned to 237/237.

**Experiment 3 — the architecture scan's own falsifiability, proven against real (if temporary) code, not
a synthetic fixture alone:** a single sabotage line —
`(registry as unknown as Invariant<KnobId>[]).push({ ...registry[0] } as Invariant<KnobId>);` — was
inserted into `gate.ts`'s own `gate` function body (compiles cleanly; `tsc` has no objection to a cast
followed by a call to a method that exists on the widened type). `npx vitest run
lib/invariants/__tests__/architecture.test.ts` was re-run: the scan flagged the exact file and line
(`gate.ts:28`), failing both the direct scan assertion and the "gate.ts legitimately uses `.map`..."
assertion (which shares the same `findMutationOffenses` call over `gate.ts` specifically). The line was
removed and `diff` against the pre-sabotage backup confirmed a byte-for-byte restore; the full suite
returned to 237/237 and `npm run typecheck` stayed clean.

## What this milestone does not claim

- **The cast residual is not closed.** `someMutableArray as unknown as InvariantRegistry<K>` bypasses
  both the brand and the freeze entirely, and `gate` performs no runtime check that would catch it (see
  Decision 3's table and its "why not `Object.isFrozen`" discussion). This is the identical disclosed
  residual class `0001-contracts.md` and `0003-evidence.md` already name for their own casts — not a new
  kind of gap this milestone introduces, but not solved by this milestone either.
- **`gate` does not validate that `registry` was actually produced by `createInvariantRegistry`** — it
  trusts its own declared parameter type, the same trust boundary every function in this codebase places
  at its own signature. A forged-but-well-typed `InvariantRegistry<K>` (via the cast above) is
  indistinguishable from a genuine one to `gate`'s own logic.
- **This milestone builds no domain and no arbitration.** `gate` consults no policy constant, no
  prior-adoption state, and no `AdaptationDecision` — it is a lookup, full stop, matching the plan's own
  M4 scope line. Whether a delta ultimately adopts, holds, or reverts is entirely M5's job (unbuilt);
  this file only answers "is this knob off-limits at all."
- **No claim is made about `lib/arbitrate/arbitrate.ts`'s own future signature or behavior** (M5,
  unbuilt) beyond what plan §4 already states in prose — this milestone does not pre-build or guess at
  that function's shape.
- **The `lib/gate/**` vs. `lib/invariants/**` mismatch (Decision 0) is resolved by this milestone in
  favor of the three pre-existing, mutually-agreeing sources, not by asking a verifier to adjudicate it
  after the fact** — flagged here, in the PR description, and in this session's own handback report, so
  a human reviewing this milestone sees the discrepancy exists and which way it was resolved, rather than
  silently inferring one path was simply a typo.
