1 · The Locked Spec (what we are building)

Cognitive job: Given a candidate change (BehaviorDelta) to one knob of an agent's own behavior, and a stream of independent, per-occasion evidence (Episodes) bearing on it, decide whether that change has earned the right to stick — corroborated across genuinely distinct occasions, not merely repeated — while an absolute, no-escape-hatch freeze on a fixed set of invariant-protected knobs refuses to let any amount of evidence touch them at all, and a previously adopted change that turns out to have made things worse can be honestly and provably reversed. See .genesis/PLAN.md §1–2 for the full claim and closed vocabulary.

Inputs: a typed BehaviorDelta naming one KnobId plus a from/to pair, and an Episode[] each carrying a contextId (the unit of independence) and a closed "helped" | "neutral" | "harmed" outcome — never a numeric score standing in for corroboration.  →  Outputs: a closed AdaptationDecision (adopt · hold · revert · frozen), always paired with the EvidenceTally that licensed it (or, for frozen, the Invariant that forbade it outright).

Autonomy level: Fully autonomous end-to-end — tallying evidence, gating against invariants, and ruling adopt/hold/revert/frozen all happen without a human in the loop. What is deliberately NOT available to any engine milestone, at the type level, is a way to widen, mutate, or bypass the invariant list at runtime: an invariant-protected knob has no escape-hatch lane at all, unlike agent-control-tower's human-authorized forced halt.

Failure tolerance: Fail toward the weaker, more conservative decision, never toward a fabricated stronger one. A delta below MIN_DISTINCT_CONTEXTS_ADOPT must return hold with an explicit distinctContextsNeeded — never a silently optimistic adopt. A single post-adoption harmed episode must not, on its own, trigger revert — the revert bar is lower than the adopt bar (the disclosed asymmetry in §1/§3 M5), but it is not zero. N episodes from one contextId are never worth more than distinctContexts: 1, no matter how large N is.

Filled during Genesis (G0–G2, .genesis/PLAN.md), following the shape used in agent-control-tower's own .genesis/DONE.html (the current house standard) — content is project-specific, structure only is borrowed. No engine code exists yet: M1 (contracts) is a separate milestone with its own PR and its own verifier.

2 · Definition of Done (binary gates — checked by the VERIFIER, not the maker)

Dependency direction inward, zero cycles: lib/contracts → lib/evidence and lib/invariants → lib/arbitrate → domains/support-triage, one-directional (modular-architecture gate)
npm run typecheck clean AND npm test green
One verify pass by a separate agent/model (L4)
No milestone's freeze boundary touched by a later milestone (freeze-boundary gate — the independent verifier's first job on every milestone)
A frozen AdaptationDecision literal carrying a tally field must not compile; a source-scan test proves no function under lib/invariants/**'s non-test source constructs, mutates, or spreads a modified invariants array (no-runtime-escape-hatch gate, from M1/M4)
AdaptationDecision is exhaustively matched via an assertNeverAdaptationDecision helper, proven live by adding a 5th variant and confirming every call site fails to compile (exhaustiveness-is-live gate, from M1)
tally is proven order-independent across every permutation of an episode set, dedups strictly by contextId (never episode count), and rejects a hostile (throwing-getter/Proxy) episodes array as a typed failure, never an uncaught exception (pure-and-hostile-input gate, from M3)
A delta targeting an invariant-protected knob resolves frozen whether it has zero episodes or ten thousand, all "helped" — evidence quantity or quality never changes the gate's answer (evidence-cannot-buy-a-frozen-knob gate, from M4/M5)
arbitrate never selects adopt below MIN_DISTINCT_CONTEXTS_ADOPT nor revert off a single post-adoption harmed episode, and never lets two deltas targeting the same live knob both resolve adopt at once (asymmetric-bar and single-live-delta-per-knob gate, from M5/M7)
The failure suite's ten cases each assert a specific typed result, not merely "no exception thrown," including the disclosed, unsolved cumulative-drift case (failure-suite gate, from M7)
The live demo URL injects distinct-context episodes and produces the same AdaptationDecision sequence as npm run demo:triage's own fixture, checked by an independent verifier comparing outputs directly (deliverable gate — the brief requires a live demo)
A clean clone plus npm ci plus typecheck plus test passes with no credentials configured (clean-clone gate)

A milestone is DONE only when every applicable box above is checked by the verifier, and never by the building agent marking its own work. This genesis repo has no engine code yet — every gate above becomes checkable starting with M1's own PR and its own verifier.
